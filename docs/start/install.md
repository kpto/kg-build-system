# Install

kg-build-system is a Python library with a small `kbs` command-line tool. A
project that uses it is an ordinary importable Python package: your declarations
are Python modules, and your build entry point is a Python module you run.

## Requirements

- Python 3.12 or newer. The package declares `requires-python = ">=3.12"`.
- No database server is required to get started. The file output module writes
  JSON Lines; a Neo4j target is optional.
- DuckDB and the other runtime dependencies are installed with the package.
  You do not install a query engine separately.

!!! note "Use a virtual environment"
    Install kg-build-system into the environment that runs your project. Keep
    the project's own dependencies and the framework in the same environment so
    `kbs` and `python` refer to the same installation.

## Install the package

Install the framework checkout that contains the version this guide describes
into a fresh environment:

```bash
python -m venv .venv
source .venv/bin/activate
pip install /path/to/kg-build-system
```

With uv, add the same checkout to a project:

```bash
uv add --editable /path/to/kg-build-system
```

Replace `/path/to/kg-build-system` with the checkout's real path.

Confirm that both the import and the command exist:

```bash
python -c "from kg_build_system import Table, compile, build; print('kg-build-system ready')"
kbs --help
```

The `kbs` command line exposes `generate`, which creates and maintains generated
data contracts. Compilation and building are done from your Python entry point,
not from the CLI.

## Create a project

The examples in this guide use one importable package inside a project
directory. The package name is also the namespace that `compile()` scans.

```text
people-graph/
  pyproject.toml
  people_graph/
    __init__.py
    data/
      people.csv
    table/
      __init__.py
    topology/
      __init__.py
    bindings/
      __init__.py
    build.py
```

A minimal `pyproject.toml`:

```toml
[project]
name = "people-graph"
version = "0.1.0"
requires-python = ">=3.12"
dependencies = [
    "kg-build-system @ file:///path/to/kg-build-system",
]
```

Create the directories and empty package markers:

```bash
mkdir -p people_graph/{data,table,topology,bindings}
touch people_graph/__init__.py \
      people_graph/table/__init__.py \
      people_graph/topology/__init__.py \
      people_graph/bindings/__init__.py
```

Add the sample feed:

```csv
person_id,name,city
p1,Ada,London
p2,Grace,New York
```

Save it as `people_graph/data/people.csv`. The dependency line points at the
same checkout; replace the path before installing the project with
`pip install -e .`.

The package name appears in every import, such as
`from people_graph.table.people import PeopleTable`. Run project commands from
the directory that contains `people_graph/`, not from inside the package. The
[next page](project-layout.md) explains what each directory is for.

## Generate the table contracts

!!! tip "Optional for the first walkthrough"

    [Your first graph](first-graph.md) writes its two tables by hand so that
    every line is visible. Skip this section if you want to start there, and
    return when you want to infer contracts from a real source.

A generated table contract is created from a request in an author-owned
`__init__.py`. Put this in `people_graph/table/__init__.py`:

```python
from kg_build_system.code_generation import generation
from kg_build_system.code_generation.builtins import (
    DataContractInferenceConfig,
    InferDataContractProvider,
)

people = generation(
    InferDataContractProvider,
    DataContractInferenceConfig(
        source="../data/people.csv",
        mode="table",
    ),
)
```

The source path is resolved from the request file, so `../data/people.csv` means
`people_graph/data/people.csv`. The assignment name, `people`, is the request
identity and the name of the generated package.

Run the generator from the project directory:

```bash
kbs generate --project .
```

It writes a package beside the request:

```text
people_graph/table/
  __init__.py                 # your generation request
  people/
    __init__.py               # generated contract
    .kbs-generation.json      # generated ownership record
```

The generated contract is an ordinary `Table` declaration:

```python
# Generated by kg-build-system. Do not edit manually.
from kg_build_system import Field, Table, TableOptions, field


class PeopleTable(Table):
    options = TableOptions(name='people')
    person_id: Field[str] = field(name='person_id')
    name: Field[str] = field(name='name')
    city: Field[str] = field(name='city')
```

Each generated member names only its value type. A top-level `| None` is never
written: `field()` strips it, because source access owns presence. The file
header records what the source declared — `required`/`optional` for Parquet, or
"all members nullable" for CSV and JSON — and the manifest records a source
digest. That claim is provenance, not a blueprint field type: every generated
member still reads as a nullable selection. Handle it with
`alter_rows().drop_null()` or `default_to()` rather than assuming a value is
there. See [types and nullability](../concepts/types.md) for the two behaviours.

!!! warning "Do not edit generated files"
    Generated packages are owned by the generator. Change the request, then run
    `kbs generate` again. In review, a hand-edited generated file is reported as
    a conflict rather than accepted. Handwritten contracts belong in their own
    modules, not in a generated package.

`mode="table_group"` produces a `TableGroup` package with nested groups for a
directory of related relations; `override` can declare a type the reader sniffs
as text, such as a timestamp. Both are shown in
[data contracts](../concepts/data-contracts.md).

!!! note "Following the first graph"
    The walkthrough writes its tables by hand. If you generated `people/` above,
    use a fresh project package for it, or remove that generated package first;
    two declarations with the same logical table name must not coexist.

## Watch while editing

`kbs generate --watch` runs one generation pass, then watches the project and
regenerates when a declaration or source changes:

```bash
kbs generate --project . --watch --debounce 500
```

- `--debounce` is in milliseconds and must be greater than zero; the default is
  300. It batches a burst of file changes into one pass.
- The watcher follows `.py`, `.json`, `.toml`, `.yaml` and `.yml` files under the
  project, ignoring caches, virtual environments and VCS directories.
- An invalid edit is logged and the watcher keeps running; fix the file and save
  again.
- `--watch` cannot be combined with `--check` (watching is not a CI check) or
  with `--regenerate` (which is one explicit re-observation pass). The CLI
  refuses both combinations.
- Press Ctrl+C to stop. The initial pass and every later pass write generated
  files in place.

## Verify the project

Check that generated output still matches its requests:

```bash
kbs generate --project . --check
```

A zero exit status means the generated packages are current. This is the command
to run in CI before a build. `--check` does not re-read the source data; add
`--regenerate` when you want every provider to observe its source again:

```bash
kbs generate --project . --check --regenerate
```

Then verify that the contract imports and that the CLI sees the project:

```bash
python -c "from people_graph.table.people import PeopleTable; print(PeopleTable.__name__)"
```

You should see `PeopleTable`. If that import fails, the package path or the
generated filename is wrong, not the graph declarations.

!!! tip "The generated contract is a starting point"
    Generated declarations are deliberately plain `Table` and `Struct` classes.
    Add descriptions, handwrite a contract when a feed needs types inference
    cannot supply, and keep reusable derived grains in a projections module
    outside generated packages.

## What to remember

- A project is an importable Python package. `compile()` scans that package, so
  keep declarations at module level.
- Generate table contracts from requests with `kbs generate`; edit the request,
  never the generated package.
- Run `kbs generate --check` in CI so generated code cannot drift from its
  requests. Use `--check --regenerate` when you also want to detect changes in
  the source schema.
